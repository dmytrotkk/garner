# garner foundation

Private, local-first personal finance app: a macOS desktop app on Tauri with a browser build for development, mobile later.
Decisions confirmed 2026-09-20. Versions were verified live on that date: re-verify before installing.

## Roadmap

1. Foundation + crypto portfolio: EVM chains, watch-only addresses and manual holdings, balances plus value history. No transactions, no PnL.
2. Subscriptions and salary, manual entry. Behind imports, see Later.
3. Imports into a ledger, order agreed 2026-10-04 and changed 2026-10-05: bank statements first (Revolut, Santander Portugal and ActivoBank done), then categories and merchants with the AI categorizer, transfers between own accounts, spending and budgets, exchange exports (Kraken, Coinbase) once sample exports exist, then lots and taxes. Designed in `ledger.md` and `ai.md`.
4. AI chat over the data, AI-generated live dashboards.
5. Later: mobile, sync.

Base currency USD, multi-currency fiat from day one. Third-party indexer APIs are fine with own keys stored locally. Open source under MIT: licenses and API terms stay distribution-safe.

## Product decisions

- Crypto v1 covers 7 EVM chains, watch-only addresses and manual holdings, with balances and daily value history. DeFi positions and tokens CoinGecko does not list are out of scope for now.
- An institution is a named group of accounts. An account is one address or a manual account, whose holdings are typed by hand or fed by imports. At an institution every account the file names is a garner account (Revolut Current and Savings are two), and the sub-wallets of an exchange are parts of one account. Each institution has its own total, sidebar entry and page. It was called a wallet until 2026-10-04: everywhere else a wallet is an address, an account or an exchange's own sub-wallet, while institution is the word most finance apps and the bank aggregators use for this level (a survey of 80 of them). Own addresses and cash sit in an institution the user names.
- Only real, popular tokens are tracked: the sync discovers only the top 1000 coins by market cap. Junk is never shown: an asset the ledger moved but the list does not know gets an unpriced row (`ticker:<SYM>`, `ledger.md`) and is hidden as dust, like any position under a cent.
- No API keys by default. Keys come later only where a user opts in (exchange read-only keys, an indexer for transaction history) and never enter page JS.
- Display currency USD or EUR from Settings. Privacy mode blurs every balance, prices stay visible.
- The bar (2026-09-27): extremely simple, perfect UX, refined data classes, explicit state machines. Every stateful flow is a discriminated union driven by a pure transition function, and domain types rule out the variants the database rejects.
- AI: the user's own AI app (Claude Desktop, Claude Code, Codex, the ChatGPT desktop app) does the AI work through garner's local MCP server, and garner owns the queue, the writes and the review (2026-10-05, `ai.md`). Values may reach a model, addresses never do (masked both ways). Bank text reaches a model only through `categorize`, privacy set aside for now so categorizing gets what it needs; no other tool returns a row's memo, a kept file, an import's name, its labels or a rule, and account names never carry an account number.
- Built to be distributed (2026-09-30): nothing in the schema or the rules is specific to one user. Jurisdiction tax rules are typed constants, Portugal first, banks and exchanges are parsers, and a user's data never leaves the machine. The first set is Revolut, ActivoBank and Santander Portugal, then Kraken and Coinbase, with Portugal's tax rules (`ledger.md`).
- Imports (agreed 2026-10-04, `ledger.md`): a file is dropped once and feeds every account it names. Any window is accepted: files join by key, the first printed balance is an opening and a later disagreement shows as a hole, never as a refusal. Nothing is written before a preview is confirmed.
- Fiat (2026-10-04): a bank account is a manual account holding `fiat:*` assets on the ledger. Totals split fiat from crypto. A fiat balance may be negative: it subtracts from net worth and shows no share. Typed holdings stay unsigned.
- Transfers, categories and budgets (2026-10-04): a transfer between own accounts pairs without a click on a twin (the same instant, the same words and exact opposite amounts in two own accounts, 2026-10-07); a fit within 4 days is proposed and decided one by one; identity (the same `ref`, an own address) and saved routes come with their sources. A category (reworked 2026-10-05) comes from a choice on one movement or from a rule for its party, the user's or the AI's, matched by equality; its type is expense, income or transfer, the last neither spent nor earned, so categories ship before pairing. A budget is a target per category, valid from a month on.
- UI reference: the Cursor app in light theme. New pages are prototyped in the app first, then refined from feedback.

## Rejected, and why

- TanStack Start, SSR and server functions: a bun backend dies at the Tauri wrap and sidecars do not exist on iOS, so all logic is portable TypeScript behind the Host port.
- Sync frameworks (LiveStore, Zero, Evolu, Jazz, Electric, PowerSync): every one needs a server.
- tauri-plugin-sql: no transactions and no iOS, so Tauri gets own `rusqlite` commands.
- Drizzle 1.0: still a release candidate with sqlite-proxy being reworked when chosen, so Kysely as a cold builder.
- Zerion and other indexers for balances: they need keys. PublicNode RPC with list-driven discovery needs none.
- Token logos from web3icons (247 of 891 coins, inconsistent tiles) or CoinGecko image URLs (a migration, mixed shapes): the DefiLlama icon CDN won.
- EvilCharts vendored whole (5.7k lines, motion, d3): distilled into slim primitives instead.

## Architecture

```
routes + ui  ->  data/<feature>.ts   Kysely queries, domain logic, provider adapters
                      |
                  Host port          query, batch, migrate, backup, transport, icon, links,
                      |              address; Relay and menu on the desktop
                 /          \
    bun host (browser dev)    Tauri host (macOS, iOS later)
    data/garner.db            ~/Library/Application Support/money.garner/garner.db
```

Rules:

- All logic is portable TypeScript in the bundle. Each host is dumb and disposable: SQL, fixed provider fetches, logo bytes, client registration and, on the desktop, the MCP line relay and native context menus. No server functions, no sidecar.
- Reads run on a read-only connection. All writes pass through one `write()` function. Routes read in loaders, and a write re-runs them through `router.invalidate()`: no query cache library.
- `migrate` runs with foreign keys off inside one transaction, then `foreign_key_check`. Migrations are guarded by a `migration` table, and a database with more of them than the app knows, written by a newer Garner, is refused with that message before anything is touched (D12), so an older build never misreads it.
- The bun host rejects any request that is not same-origin (`sec-fetch-site`), on top of Vite's host check. Vite runs with `server.cors: false` and `vite.config.ts` narrows `server.fs.allow` to `index.html`, `src`, `cards` and `node_modules`, so no path serves `data/` or `sample-data/`.
- Providers are a fixed list behind `host.transport(provider, path, body?)`: coingecko, frankfurter, llama, publicnode. No generic proxy. A host returns the body or, for any other status, the status with its raw Retry-After, and never decides; `gate` (`src/data/gate.ts`), wrapped once around the transport in `main.tsx` and for the dev MCP server, is the `Fetch` every caller gets: a 429 or 503 pauses that provider in memory for its Retry-After, at least a minute and at most a day, calls during the pause are refused at once with its name and the wait, and nothing retries in a loop. None needs a key today. A future key lives host-side in `.env` and never enters page JS.
- The bun host is mounted as Vite middleware: one process, one port.
- Quantities are exact `bigint` base units stored as TEXT. Prices are float estimates. Value is computed at read time. SQL filters, TypeScript sums.
- Money is stored and computed in USD. The display currency is applied at render time by `Money`, with the latest `fiat:*` rate from the `price` table; a currency without a stored rate is an error that `setCurrency` makes unreachable. `Money` takes a number, which is USD, or `{ amount, currency }`, which is already in the display currency and renders as is: history converts each day at the rate of that day and hands its points over that way, tax values are computed in the rule's currency from the legs, and a budget line in its budget's asset (`ledger.md`).
- Preferences live in the `setting` table (key, JSON value), are read by the root loader, and change through `write()` plus `router.invalidate()` like any other data.
- Ids are UUIDv7. Mutable rows carry `updatedAt`, except user state that is replaced whole by its key: `decision`, `route`, `rule`, `choice`, `note` and `identity`, later `budget`. Facts have deterministic keys: a same-day price replaces its row, a same-day observation replaces an older one (from migration 7 never a newer one), imported entries are rebuilt with a plain insert (`ledger.md`, Apply and remove), and everything else is insert-or-ignore.
- Facts and derived values never share a table (2026-09-30, kept by the imports plan of 2026-10-04). Observations (`balance`) and movements (`entry`) are stored; closings, coverage, history, transfers, flows, spending and lots are computed on read (`ledger.md`). Balance snapshots are captured from day one: without transaction history they cannot be backfilled. Daily prices and FX rates can: every sync fills the days it missed from DefiLlama `/chart` and a Frankfurter date range.
- Imports follow `ledger.md`: an import keeps its file whole and feeds accounts through a route frozen on its row, entries and file observations are never edited, only rebuilt from the kept files, a row without an id is keyed from itself (`row:<stamp>:<unit>:<amount>:<n>`), and wall-clock text is stored as printed, read as if it were UTC. Parser output is never stored, so its shape grows with the sources.
- SQL stays within upstream SQLite 3.53 features: bun runs Apple's fork on macOS (`legacy_alter_table` on) and the desktop app bundles upstream, so a migration runs on both before it ships: `bun test --preload` with a file calling `Database.setCustomSQLite` on Homebrew's upstream build runs the suite on upstream.
- Sync is a later add-on: per-device delta files or CloudKit records merged last-write-wins. The live SQLite file never enters iCloud.
